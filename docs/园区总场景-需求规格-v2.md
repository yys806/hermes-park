### 2.1 点击地块 → 详情分三栏（Tab）

**Tab 1 · 职责**
- 这个群是干什么的、能接什么活、边界是什么（不做什么）
- 数据源：群定位文本 + 群公告，固化成 `business.json`（我维护，可改）

**Tab 2 · 此刻在做什么（业务流）**
- 当前正在跑的业务 / 最近跑完的业务
- **完整工作流**：这次业务从哪触发 → 经过哪几步 → 现在停在第几步 → 下一步是什么 → 何时结束
- 每条业务可展开看每一轮的产出（cron 的 run-log）

**Tab 3 · 待办 + Cron（两块分开）**

*3a 待办（可写）*
- 来源：飞书云表「待办」base（唯一权威）
- 按群职责划分，尽量不重叠；跨群的放中央大厅
- 支持：新增 / 修改 / 勾完成 / 改日期 / 删除（软删）
- 只显示未完成 + 今天到期 + 未来 N 天，可切"全部"

*3b Cron（只读 + 可重跑）*
- 来源：本地 cron 注册表（当前 74 条，其中每日/每周在跑约 30 条）
- 每条显示：名称、归属地块、周期（每天/每周/每 N 分钟/一次性）、下次运行、最近状态（成功/失败/未跑）、失败原因
- 点开：完整报表（这次运行的输出）+ 历史（最近 N 次）
- 失败项：按钮「重跑」→ 直接派给所属群聊执行

### 2.2 同步机制（我提的方案）

**原则：云表 = 唯一权威，本地 = 镜像，页面 = 读写入口。**

```
页面操作
  → 本地 Node 服务 /api/todo（唯一写入口，不直连飞书）
    → ① 写飞书云表（Bitable）
    → ② 写本地镜像 JSON（供离线/批量读）
    → ③ 追加一条变更日志 changes.jsonl
  ← 返回新版本号
```

- 冲突：每条记录带 `updatedAt` + `rev`；写时带 rev，服务端比对，不一致返回 409 → 页面提示"远端已变更，是否覆盖/刷新"
- 断网：写本地 `pending_writes.json` 队列，恢复后按序回放；页面角标显示"待同步 N 条"
- 只读项（cron 报表、cron 状态）直接读本地文件，不落云表，避免污染待办表
- 云表字段对齐：我的待办看 `截止日期`，彩虹的看 `截止日`（已知差异，代码里分别处理）

## 3. 任务包裹动画（第 2 条）

**核心原则：没有真实业务，园区里就没有包裹在跑。**

| 环节 | 表现 |
|---|---|
| 产生 | 在源地块生成一个包裹（实体小箱/胶囊），带微光 |
| 运输 | 沿该地块与中央大厅之间的传送带移动到目标地块 |
| 处理中 | 目标地块**突出显示**：夜间=自己亮灯；白天=悬浮进度环/转圈图标 + 名称气泡加"处理中" |
| 可点开 | 点悬浮标记 → 显示：第几轮 / 已运行时长 / 每轮做了什么 |
| 完成 | 包裹沿带返回中央大厅，进入穹顶后消失（=归档），穹顶做一次轻微脉冲 |

- 包裹 = 一次 cron 运行 **或** 一次业务事件（如某条待办被完成）
- 包裹数量与真实并发数一致，不造"一直流动"的假动画
- 夜间同时点亮的处理中地块不超过 3 块（性能 + 视觉）

## 观感升级提案（对标参考视频「卡兹克」的微缩黏土质感）

分三档，按"性价比"排序。**建议先做 A 档 5 项，出单块对照图确认后再铺全园（P0.5 风格校准）。**

### A 档 · 立刻能做、成本低、观感提升最大
1. **轻度景深 / 移轴感**：聚焦地块清晰、远景虚化，微缩模型味的核心来源。
2. **接触阴影 + SSAO**：物体与地面接触处加深，才有"摆件放在沙盘上"的真实感。
3. **色彩分级**：暖调 LUT + 轻微暗角 + 灯罩 Bloom。
4. **昼夜渐变**：切换不硬切，3–5 秒过渡（太阳角度滑动、天空色温渐变、灯逐盏亮起）。
5. **云影飘过地面**：一层缓慢移动的软阴影噪声，画面立刻"活"。

### B 档 · 中等成本、明显加分
6. **沙盘边缘处理**：整个园区做成浮岛/切边沙盘，边缘草丛灌木过渡。
7. **环境动态件**：树梢轻微摇摆、旗子飘动、烟囱冒烟、水面微光。
8. **镜头语言**：自动巡航、聚焦时缓入缓出推镜、点击地块轻轨道运动（替代现在的硬切）。
9. **演示模式**：一键把一整天压缩到 60 秒播放（日出→日落→夜景），可直接录屏做宣传。

### C 档 · 锦上添花 / 要谨慎
10. 小 NPC 走动（微缩世界有人味，但要模型和动画）。
11. 雨天地面湿滑反光、雪天积雪覆盖的材质切换。
12. 界面音效（点击/开关），有变吵的风险。
13. 一键录制分享视频。
