## 第 1 章 · 项目定位

### 1.1 一句话

把现在"能看"的 3D 微缩园区，升级成**能看 + 能读 + 能管**的业务驾驶舱：
外观跟着真实时间天气走；点地块能看到这个群在干什么、还要干什么；
有活干的时候园区里才跑包裹；任务信息直接在大屏上管，改完自动同步本地与云表。

### 1.2 三层价值

| 层 | 内容 | 价值 |
|---|---|---|
| 看得爽 | 卡通黏土微缩风格 + 电影级后期 + 真实日照 | 愿意点开、愿意截图、能出片 |
| 看得懂 | 点地块 = 这个群干什么、正在干什么、下一步干什么 | 一眼看清 8 条业务线的状态 |
| 管得动 | 待办能加减勾、cron 能看能重跑、改完云地同步 | 不再靠翻群聊记录 |

### 1.3 三条验收直觉（用户视角）

1. 夜里打开，**只有我点的那块地亮**，别处黑着。
2. 点开"深度学习"，能立刻看到：这个群管什么 → 报告现在做到第几步 → 还有哪些待办没做 → 哪个 cron 昨晚挂了、点一下能重跑。
3. 有任务在跑时园区里才出包裹，没任务时干干净净。

## 第 5 章 · 需求总表（逐条标准化）

> 每条都可追溯到用户的原始表述；★ = 用户已拍板的具体口径。

### 5.1 视觉与光照

| 编号 | 需求 | 口径 |
|---|---|---|
| V-1 | 夜间只有点选的地块发光 | ★ 点选=聚焦，**一直亮到切回全景或点别的地块**；未选中不发光，不因相邻地块发光而被带亮 |
| V-2 | 处理中的地块在夜里也要看得出来 | ★ 真实光源只给聚焦地块；处理中用**进度环 + 灯罩微光**表达，不占用真实光照 |
| V-3 | 删除悬停高亮 | 悬停只显示地块名称气泡，不做整块高亮（避免误识别） |
| V-4 | 明暗一致 | 无阳光/灯光时全园各块亮度基线统一（统一曝光、统一环境光、材质不额外自发光） |
| V-5 | 白天的聚焦反馈 | ★ 顶部显示「已聚焦：XX」+ 名牌强调色 + 相机飞入，**不改地块明暗** |
| V-6 | 白天处理中 | ★ 地块上方悬浮**进度环 + 状态文字**，点击展开轮次 |
| V-7 | 完成后归档 | 包裹沿带返回中央大厅，进穹顶消失，穹顶做一次轻微脉冲 |

### 5.4 同步机制

| 编号 | 需求 | 口径 |
|---|---|---|
| S-1 | 唯一写入口 | 页面不直连飞书；所有写操作走本地 `/api/*`，由服务端持有凭据 |
| S-2 | 双写 | ①写飞书云表 → ②写本地镜像 → ③记变更日志 → 返回新版本号 |
| S-3 | 冲突处理 | 记录带 `rev`/`updatedAt`；写时比对，不一致返回 409 → 提示"远端已变更" |
| S-4 | 离线 | 断网写入队 `pending_writes.json`，恢复按序回放，页面角标显示待同步数 |
| S-5 | 降级 | 云表不可用时页面转只读缓存，不白屏 |
| S-6 | 安全 | 写操作二次确认 + 保留旧值可撤销；删除一律软删 |

## 第 7 章 · 技术方案

### 7.1 总体架构

```
浏览器（viewer2 前端）
   │  只读 GET /api/*、写 POST/PATCH /api/*
   ▼
本地 Node 服务（home/server/server.js 扩展）
   ├─ 飞书云表 API（读+写：待办 / 影视；只读：资产 / 彩虹出路）
   ├─ 本地文件（business.json / bindings.json / 业务流定义 / 每日归档）
   ├─ cron 数据（executions.db + output/*.md）
   ├─ hermes cron run（重跑）
   └─ Open-Meteo（天气，带 5 分钟缓存）
```

**凭据只在服务端**（`D:/hermes/.env`），前端永远拿不到。

### 7.2 同步机制（S-1…S-6 的落地）

1. 每个可写实体带 `rev`（整数）与 `updatedAt`。
2. 写请求必须带 `rev`；服务端与云表现值比对，不一致 → 409 + 远端最新值。
3. 写成功：云表 → 本地镜像 JSON → `changes.jsonl` 追加 → 返回新 rev。
4. 网络失败：写 `cache/scratch/pending_writes.json`，指数退避重试；页面右上角显示"待同步 N"。
5. 云表读失败：返回本地缓存并打 `stale: true`，页面显示"离线数据 · HH:MM"。

### 7.3 待办 ↔ 地块绑定表

- 载体：**新建独立多维表格**（不动三张老表），名「园区绑定」。
- 字段：待办记录 ID / 待办标题 / 来源表（我的|彩虹的）/ 归属地块 / 认领人 / 绑定时间 / 状态（有效|软删）/ 同步时间。
- 自动预填：每天按「类型」字段先猜地块（生活→家人、学业·科研→学习科研、考公·求职→彩虹事务、其他→中央大厅），已手工指定过的不覆盖。
- 页面来源标记：自动（灰）/ 手工（蓝），点一下就能覆盖。
- 软删：状态改 `软删` + 时间戳，页面不显示，云表记录不动（可一键恢复）。

### 7.4 影视清单写权限边界

- **允许改**：状态（待看/在看/已看）、看完日期
- **只读**：「我的评分」「短评」「豆瓣评分」等用户私人字段
- 写前必须 `GET .../fields` 核对列名；写完回读验证

### 7.5 cron 归属推导

1. `job.deliver` 的 chat_id → 群 → 地块（映射表内置）
2. 无投递或投递到"Home"的 → 看 job 名关键词（备份/服务器/域名→资产管理；文献/论文→学习科研…）
3. 仍推不出的 → 归中央大厅，并在 `unmapped_jobs.json` 列出来问用户

### 7.6 业务流定义（示例结构，初期约 8–12 条）

```json
{
  "id": "dl-exp1-report",
  "name": "深度学习实验一报告",
  "plot": "learn",
  "steps": [
    { "job": "<job_id>", "title": "资料与环境准备" },
    { "job": "<job_id>", "title": "跑 8 个示例并出图" },
    { "job": "<job_id>", "title": "写报告初稿" },
    { "job": "<job_id>", "title": "润色与提交" }
  ],
  "deadline": "2026-11-15",
  "manual": true
}
```

### 7.7 每日归档（补 executions.db 只留 1000 条的短板）

每天 00:10 把当天 `executions` 增量写 `cron/state/exec_archive/YYYY-MM.jsonl`（几 KB），页面读 90 天内的报表从归档取。

| 低 | 无后期、无阴影、DPR 1 | 60 fps |
