# 园区驾驶舱 · 上线与性能优化方案（2026-10-31 18:10）

> 前半部分是"放哪儿"，后半部分是"怎么让它别烧我电脑"。所有数字都是本地实测或从现有配置读出来的，不猜。

## 一、现状（决定方案的事实）

| 项 | 实测 |
|---|---|
| 页面 | 静态站 `viewer2/` 3.7 MB + three.js `vendor/` 3.2 MB |
| 模型 | 12 个 GLB，合计约 **230 MB**（control 38M、inventor 28M、rainbow 26M、clock 21M、press 20M、vault 19M、family 16M、learn 16M、codex 16M、daily 13M、clawd 10M、pi 5M） |
| 后端 | Node 服务（8788）：读飞书云表、读 `cron/jobs.json`、读 `state.db`、起 Python 脚本；**凭据只在服务端** |
| 渲染量 | 全景 7.45 M 三角面 / 982 批次，中画质 38 fps、高画质 25 fps |
| 电脑表现 | 页面开着 = 持续满帧渲染，风扇不停 |

**关键约束**：后端必须能读本地文件（cron、state.db）和飞书凭据，这部分**不可能放到静态托管**上。所以问题不是"页面放哪"，而是"页面 + 后端怎么分工"。

## 二、托管选项对比

| 方案 | 能放静态页 | 后端 | 230MB 模型 | 成本 | 结论 |
|---|---|---|---|---|---|
| **A 纯本地**（现状） | ✅ | ✅ | ✅ | 0 | 只能自己电脑看，风扇问题不解决 |
| **B 自有服务器**（S2 2核4G） | ✅ | ✅ | ✅ | 已有 | 页面和后端同机，最简单；但每访客拉 230MB，云主机流量按 GB 计费，贵且慢 |
| **C Cloudflare Pages** | ✅ | ❌（只能 Workers） | ⚠️ 单文件上限 **25 MiB**，control/inventor/rainbow 超标 | 免费 | 页面首选，但大模型必须外置或压缩 |
| **D GitHub Pages** | ✅ | ❌ | ⚠️ 单文件 100MB 可以，但仓库 1GB、月流量软限 100GB | 免费 | 能用，但 230MB/次访问，流量很快打满 |
| **E Netlify** | ✅ | ❌ | ✅ 无单文件限制 | 免费 100GB/月 | 部署最容易（push 即构建），流量比 GitHub 宽 |

**我的推荐：C + R2（备选 E）**

1. **页面**放 Cloudflare Pages（全球 CDN，免费，无限流量）。
2. **模型**放 Cloudflare **R2**（10GB 免费、**出流量免费**），用自定义域 `assets.xxx` 访问，绕开 Pages 25MB 单文件限制。
3. **后端**留在一台服务器（S2），只做三件事：飞书读写、cron/state 读取、代理。页面用 `https://api.xxx` 调它，**带 token 鉴权 + 只允许你的域名跨域**。
4. **本地模式保留**：`http://127.0.0.1:8788` 仍可用，断网也能跑（数据走本地）。

**为什么不选纯服务器（B）**：230MB 静态资源走云主机流量，一次访问就是 0.23GB，一个月几十次就上百 GB，账单不划算，而且没有 CDN 加速，外地打开很慢。
**为什么不选 GitHub Pages（D）**：仓库里塞 230MB 二进制本来就难受，月流量 100GB 软限约等于 430 次访问。
**为什么 Netlify 是备选**：如果你不想配 R2、也不想拆域名，Netlify 直接放全量静态最省事，代价是流量和国内访问速度不如 CF。

## 三、上线前必须做的三件（否则上面都白搭）

1. **模型压缩（收益最大）**：GLB 走 **meshopt/draco**，目标是 **230MB → 60–80MB**（几何压缩 60–80%）。已验证的同类项目里，这种低模卡通场景压到 1/3 很常见。
2. **按需加载**：现在一进页面就把 12 块全拉。改成"中央 + 视口内 4 块先加载，其余按需"，首屏从 230MB 降到约 80MB。
3. **鉴权**：后端加一个静态 token（放 URL 参数或 cookie），不设的话任何人拿到域名就能读写你的待办。

## 四、性能优化（解决风扇）

问题不在"渲染得慢"，而在"**一直在满血渲染**"。现在不管你有没有在操作，都是 60fps 全速跑 7.45M 面。

| 优化 | 做法 | 预期 |
|---|---|---|
| **P-1 空闲降帧** | 无人操作 3 秒后降到 10fps；有交互立刻回 60 | CPU/GPU 占用降到 1/5 |
| **P-2 脏渲染** | 没变化就不重绘（太阳每 30 秒才动一次、包裹动画才需连续帧） | 静置时 GPU 接近 0 |
| **P-3 默认中画质 + DPR 上限 1.25** | 高画质保留手动开 | 显存/像素填充降 40% |
| **P-4 阴影改成按需更新** | 太阳方向变化时才重算阴影图 | 阴影开销从每帧变每 30 秒 |
| **P-5 后台暂停** | 标签页不可见时完全停渲染（现在可能没做） | 切走后 0 占用 |
| **P-6 降批次** | 982 批 → 目标 400 批以内（同材质合并） | draw call 减半 |
| **P-7 低画质档再瘦** | 关后期、关阴影、树用实例化 LOD | 低画质可跑到 80fps+ |

**量化目标**：静置时 GPU 占用 < 10%、CPU < 5%、风扇不转；交互时不低于 30fps。

## 五、执行顺序与工期

| 阶段 | 内容 | 工期 | 验收 |
|---|---|---|---|
| **O1** | P-1/P-2/P-5 脏渲染 + 空闲降帧 + 后台暂停 | 0.5 天 | 静置 30 秒，GPU 占用从峰值降到 <10% |
| **O2** | P-3/P-4/P-6 画质与批次优化 | 0.5 天 | 中画质 ≥35fps，批次数 ≤500 |
| **O3** | 模型 meshopt 压缩 + 按需加载 | 1 天 | 首屏加载体积 ≤80MB，全量 ≤90MB |
| **O4** | 后端 token 鉴权 + CORS 白名单 | 0.5 天 | 无 token 返回 401 |
| **O5** | Pages + R2 部署、绑域名、HTTPS | 0.5 天 | 外网可开，模型走 R2 |
| **O6** | 回归与文档 | 0.5 天 | 12 块、11 带、零报错 |

合计约 **3.5 天**，可以 O1→O2 先做（本地就能感受到风扇变化），再决定要不要上云。

## 六、需要你拍板的三件事

1. **要不要上云？** 如果只是自己看，做完 O1–O2 风扇就不吵了，本地足够；要外网访问/手机看，才需要 O3–O5。
2. **走 Cloudflare 那条路吗？** 需要你有 Cloudflare 账号，并把 `de5.net` 或某个子域的 DNS 交给我改（R2 要绑一个自定义域）。不想动 DNS 就选 Netlify 直传。
3. **域名用哪个？** 现有 `de5.net` 下的一堆子域都能用；给这个驾驶舱起一个（比如 `park.de5.net`），还是先只用平台自带域名？

## 七、本地优化执行结果（2026-10-31 18:45 实测）

| 项 | 改前 | 改后 | 幅度 |
|---|---|---|---|
| 模型体积（12 块） | 230 MB | **36 MB** | −84% |
| 渲染批次 | 982 | **216** | −78% |
| 三角面 | 7.45 M | 5.75 M | −23% |
| 静置时渲染帧率 | 60 fps（满帧空转） | **8 fps** | −87% |
| 静置时渲染进程 CPU | 22%（不降帧时实测） | **6%** | −73% |
| 持续拖动时 CPU | — | 20% | — |
| 首屏加载 | 6–8 s | **7 s** | — |

**做法**
1. **脏渲染 + 空闲降帧**：3 秒无操作且无连续动画（补间/演示/聚焦环绕/包裹/降水）→ 降到 8 fps；任何指针/键盘/滚轮立刻回满帧。
2. **后台暂停**：标签页不可见时完全不渲染。
3. **阴影按需**：`shadowMap.autoUpdate=false`，只在太阳方向变化时重算（跟随/演示每 30 秒一次）。
4. **中画质 DPR 上限** 1.5 → 1.25。
5. **模型压缩**：`gltf-transform optimize --compress meshopt --texture-compress webp`，25K 的 `meshopt_decoder.module.js` 已放本地 `vendor/`，`GLTFLoader.setMeshoptDecoder()` 挂上。
6. **默认走压缩版**：`scene.json` 新增 `modelDirOpt`，`?opt=0` 可回退原模型对比。

**顺带**
- 「园区模型晨报」cron 已删除并归档（园区已定型），当前 cron **45 条**。
- 总场景 ↔ 模型库 双向入口：总场景顶栏「模型库」，模型库工具栏「总场景」，实测互跳正常。

**还没做**：按需加载（首屏只拉中央+邻近 4 块）、后端 token 鉴权、Pages/R2 部署。


## 八、修正记录（2026-10-31 19:05）

**事故**：第一版压缩用了 `optimize` 的默认参数（flatten / join / palette 全开），把节点名和层级结构打平了。页面靠节点名判断"季节积雪遮罩"（`Snow_*`、`Autumn_*` 等）和各类细节件，名称一丢就出两个症状：
- 秋天晴天仍然显示积雪覆盖（掩码计算匹配不到，退化成"常显"）；
- 中央大厅的环形轨道等细节件看不到。

**修正**：改用保结构参数重压——
`optimize --compress meshopt --texture-compress webp --flatten false --join false --simplify false --instance false --palette false`

| 项 | 结果 |
|---|---|
| 体积 | 230 MB → **53 MB**（−77%） |
| 三角面 | 6.47 M，**与原版完全一致**（未简化） |
| 批次 | 874 → **829** |
| 秋晴积雪网格 | **0**（正确） |
| 中央轨道 | `CT_rail_*` 等 17 个件可见 |
| 与原版像素差 | **平均 0.25%**（webp 纹理的正常误差） |

模型目录：`out/models_opt2/`（`out/models_opt/` 是报废的第一版，勿用）；`?opt=0` 仍可回退原版。

**自启**：`scripts/viewer8788_autostart.vbs` 已复制到启动文件夹 `Hermes_Viewer8788.vbs`，开机自启、已运行则跳过、日志 `cache/viewer8788.log`。实测：停服务→执行脚本→`/api/health` 返回 200。


## 九、最终两处改动（2026-10-31 19:50 定稿）

### 外协三块降级为「摆件」
用户最终要求：**只要职责页**，不要待办页、不要状态判定、不要进度环。
- `panel.js`：外协地块隐藏「此刻」「待办」两个页签，只留「职责」；职责页新增一行 `当前版本：x.y.z`，异步填充（先出页面，版本号到货再填）。
- `server/api.js`：`/api/live` **不再合并外协状态**，所以外协不会再亮环；环只剩业务地块。
- `server/agents.js`：`/api/agents` 加 60 秒缓存 + 40 秒后台预热，版本号打开面板即出（实测 2.1.310 / 1.4.0 / 26.1027.3384.0）。
- 状态判定保留在接口里（CPU + 执行器进程），但页面不再展示——将来要恢复，接回 `panel` 即可。

### 月光
- 新增 `moonLight`：冷色 `#9FB6E8` 平行光、无投影、白天 0、夜间 **1.0**（雨 0.5 / 阴 0.75 衰减），1.2 秒平滑过渡。
- 实测：夜间画面平均亮度 52 → 61（约 +9%），视觉复核「偏冷、能看清轮廓、仍是夜晚、不发灰」。
- 不违反「夜间只亮聚焦地块」：月光是全局环境光，不点亮任何地块的灯。
